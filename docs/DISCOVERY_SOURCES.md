# Discovery source coverage

## Active compatible sources

The collection workflow uses the complete source list from the pinned FreeNodes revision. It must not filter the list down to `github_file` entries: the pinned engine also supports `web`, `password_page`, and `youtube_resources` adapters. Each source is bounded by the engine's per-source artifact/byte budgets, per-run byte budget, request timeout, concurrency, parser admission, freshness checks, and Mihomo capability checks.

At the pinned revision, the configured web discovery sources include ClashMeta, NodeV2Ray, FreeClashNode, ClashNode, OneClash, CFmem, JichangX, ClashStair, and Datiya. The active GitHub-file sources include maintained Mihomo/Clash/V2Ray subscription repositories. Password-page and YouTube-resource adapters are also configured with bounded password-candidate policies. The exact list is version-pinned in the upstream `config.yaml`; this repository's workflow prints the active adapter counts in the Actions log.

The reserve-only `audit_sources` remain inactive in the normal publication run. They are not silently promoted into production sources.

## VPN Gate OpenVPN adapter

[VPN Gate](https://www.vpngate.net/en/) is actively queried through its official CSV endpoint, `https://www.vpngate.net/api/iphone/`. The adapter locates the CSV header, decodes each OpenVPN_ConfigData_Base64 field, parses the embedded .ovpn directives and inline CA/certificate/TLS-key blocks, and converts only the supported parameters into native Mihomo `type: openvpn` proxy entries. Official connection methods and the .ovpn workflow are documented by [VPN Gate](https://www.vpngate.net/en/howto.aspx) and [its OpenVPN guide](https://www.vpngate.net/en/howto_openvpn.aspx); Mihomo's supported OpenVPN outbound fields are documented [here](https://wiki.metacubex.one/en/config/proxies/openvpn/).

Following the source-side filter documented by CFnew's historical home-chain implementation, the adapter also excludes VPN Gate's known self-operated public VPN endpoints: hostnames beginning with `public-vpn` and addresses in `219.100.37.0/24`. This removes known directory infrastructure, not all hosting or all VPN-detected exits; every remaining volunteer relay still requires the full independent exit and risk checks. The adapter rejects profiles with missing CA material, invalid or private literal remotes, malformed ports, external credential-file references, mismatched CSV/embedded remote IPs, conflicting TLS-key blocks, or unsupported transports. VPN Gate's public credentials are represented only when the profile requests auth-user-pass; certificate-based profiles use their inline client certificate and key instead. Each generated profile is checked by the pinned Mihomo binary before admission. The normal exit echo, IP metadata, Layer3 and O-X-L gates still apply afterwards.

VPN Gate and VPNBook each contribute at most 50 Mihomo-syntax-valid candidates per run, sharing a 100-node supplemental-source cap; up to 400 FreeNodes candidates fill the remainder of the 500-node pool. Of the 80 real-exit probes, up to 40 are reserved for supplemental sources and distributed across active VPN Gate/VPNBook sources, with unused quota reassigned. The GitHub run number shifts each source's sample window so successive six-hour runs test different relays rather than repeating the same sample. Upstream country, score, ping and server IP are candidate metadata only; they never prove the actual exit IP, country, residential status or risk class. If the official API is unavailable, the failure is recorded and other productive sources continue.

Mihomo supports the OpenVPN outbound; therefore VPN Gate is not excluded merely because its source format is .ovpn. The official CSV is a rolling directory (typically around 100 rows), so short-lived country entries can disappear between scheduled runs. NodeHub keeps a 14-day candidate history, retaining at most five off-window profiles per advertised country; each run rotates a country-balanced sample of up to 50 profiles, giving US-labelled entries first look for discovery only. Profiles recovered from history are rechecked by Mihomo and then must pass the normal real-exit, ASN, Layer3 and O-X-L gates again. An old profile is not assumed live, and source country is never treated as actual exit country. The history is a public-source candidate cache, not a subscription. A VPNGate exit that Layer3 flags as VPN/anonymizer but also identifies as an ISP access network, with O-X-L ASN independently confirming ISP, is retained under the diagnostic reason `vpngate_isp_access_relay_candidate_unverified`. This is a non-publishable candidate lane only: the VPN risk score remains high, no subscription gate is waived, and independent residential proof is still required before any promotion.

## End-to-end admission remains mandatory

All compatible-source candidates are deduplicated and syntax-checked by FreeNodes, measured through Mihomo, then capped to 500 published candidates. The classification module samples at most 80 across the complete Mihomo-ranked pool and tests the real exit IP through two independent echo services. IPWhois/IPinfo, Layer3 Intel, and O-X-L evidence gates remain unchanged. A node's source label, advertised country, server address, or upstream ping score is never used as proof of exit country, residential status, or low risk.

Source discovery success is not the same as a publishable classified node. If a source yields no compatible nodes or a candidate fails the exit/risk checks, it is recorded as unavailable/rejected and is not inserted into any of the three subscription pools.


## VPNBook official OpenVPN source

The collector reads the official VPNBook OpenVPN page, extracts the current shared credentials and server directory from the page's embedded data, then requests each server's TCP-443 profile from the official `https://www.vpnbook.com/api/openvpn` endpoint using its discovered hostname and IP. If the page's embedded server JSON changes, it extracts the visible official server hostnames and resolves their current public IPv4 addresses through DNS; it does not use stale hard-coded server IPs or legacy ZIP paths. Credentials are held in memory only and are never written to source reports, logs, or diagnostics. If a VPNBook profile passes all classification gates and is published, its required login fields are necessarily included in the public subscription; these are shared credentials already displayed by VPNBook and periodically rotated. Each profile is syntax-checked with the pinned Mihomo binary before it enters the candidate pool. VPNBook candidates share the 100-node supplemental cap with VPN Gate and receive a rotating share of the 80 real-exit probes. Official page: https://www.vpnbook.com/freevpn/openvpn; official configuration API: https://www.vpnbook.com/api/openvpn.
